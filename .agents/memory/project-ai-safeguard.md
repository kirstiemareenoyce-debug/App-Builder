name: Project AI safeguard activation
description: Owner approval and accounting boundaries for project-wide AI protection.
---

Prepare safeguards offline; installation, activation and the numerical project
allowance each require explicit owner authorization. Preparing or merging the
implementation is not authorization to change the external Supabase project.

**Why:** This controls shared paid-provider access. A request allowance bounds
admissions, not dollars: one admission can incur Kimi and OpenAI charges.

**How to apply:** Keep initial installation paused until activation is approved.
Preserve consumed usage when adjusting limits, pausing, or deleting accounts.
Do not claim an emergency pause can cancel already dispatched provider calls.

The owner approved **20 requests per account and 100 across all accounts per UTC
day**, including installation, activation, and deployment of the protected chat
backend. This activation approval did not include additional paid AI tests.

**Why:** After choosing “100 not 50” for the shared policy, the owner separately
selected “Activate daily limits” for the explicitly described installation and
backend deployment.

**How to apply:** Preserve 100 as the approved project allowance unless the owner
changes it. Preserve the 20-per-account policy and existing consumption. Do not
treat this approval as permission to change allowances, reset usage, activate
other services, or run further paid tests.
